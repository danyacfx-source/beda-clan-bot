# Возможности BEDA Clan Bot

Все команды — slash-команды (64 шт.), текстовые команды с префиксом не
используются. `BOT_PREFIX` в `.env` остаётся только потому, что discord.py
требует этот параметр при создании бота.

## Поддержка и структура

| Команда | Назначение |
| --- | --- |
| `/ticket` → `/ticket_panel`, `/ticket close`, `/ticket transcript` | тикеты: панель категорий, закрытие, экспорт переписки |
| `/rules` (кнопка правил) | rules-гейт: роль выдаётся только после прочтения правил |
| `/apply_permissions` | применить схему прав к категориям |
| `/roles_required` | какие роли дают доступ к категории |
| `/setup_channels`, `/setup_roles`, `/apply_role_settings`, `/debug_channels` | первичная настройка сервера |

Автоматически: `rules_gate` выдаёт роль после подтверждения правил,
`permissions` применяет `PERMISSIONS_CATEGORIES` при старте.

Панель заявок в клан (`/ticket panel`) по умолчанию содержит текст
«ЗАЯВКА В КЛАН [BEDA]»: требования к возрасту, микрофону и адекватности, обещание
игры без обязаловки и 24/7 онлайна, запрет ЧСВ и токсичности. Текст, подпись
кнопки и эмодзи задаются в настройках сервера (`ticket_panel_*`,
`ticket_open_label`, `ticket_open_emoji`) — их видно в веб-панели. Исходные
значения лежат в `app/core/ticket_content.py`.

## Модерация

| Команда | Назначение |
| --- | --- |
| `/ban`, `/unban`, `/kick`, `/timeout` | санкции |
| `/purge` | массовое удаление сообщений |
| `/slowmode`, `/lock`, `/unlock` | ограничения канала |
| `/warn`, `/warns`, `/warn_remove`, `/warn_clear` | предупреждения |
| `/case`, `/cases` | история кейсов по участнику |

Автоматически: автомод (запрещённые слова, капс, ссылки, флуд, антиraid,
локдаун), расширенные логи (вход/выход/бан/удаление/правка сообщений — по
отдельным каналам), `logging_events`.

Настройки: `AUTOMOD_*` в `.env`.

## Временные голосовые каналы

- `/temp_panel` — панель управления комнатами в панели/через бота.
- Автоматически: создание, переименование, лимит участников, блокировка
  камеры/шеринга, удаление при опустошении, передача владения.
- Настройки: `TEMP_VOICE_TRIGGER_IDS`, `TEMP_VOICE_CATEGORY_ID`.

## Напоминания (личные)

| Команда | Назначение |
| --- | --- |
| `/remindme текст время` | личное напоминание по времени |
| `/remind канал текст время` | напоминание в канал |
| `/remind_cancel id` | отменить своё напоминание |
| `/remind_clear` | снять все свои напоминания |

Хранение — таблица `reminders`, доставка работает в фоне (цикл ~30 с) и
переживает перезапуск бота. Напоминания приватные: чужие видны только по ID.

## Ивенты (сборы)

| Команда | Назначение |
| --- | --- |
| `/event` | мастер создания ивента: 7 вопросов в личных сообщениях |
| `/event_edit id` | изменить поле ивента (создателю) |
| `/event_cancel id` | отменить ивент (создателю) |
| `/event_list` | последние ивенты сервера |
| `/event_signup id роль` | отметить участие без кнопки |

В карточке ивента живёт устойчивый селект участия: `Есть инфра`, `Есть тех`,
`Может быть`, `Сл`, `Камера`, `Не иду`. Повторный выбор той же роли снимает
отметку; «Не иду» не попадает в список участников для напоминаний.

Время вводится по Москве в формате `ДД.ММ.ГГГГ ЧЧ:ММ` и хранится в UTC.
За `EVENTS_REMINDER_LEAD_MINUTES` минут до сбора и до начала участники
получают напоминание в канал; отменённые ивенты не напоминают.

Хранение — таблицы `events` и `event_signup`, поэтому ивенты, отметки и флаги
напоминаний переживают перезапуск.

## Где играем

| Команда | Назначение |
| --- | --- |
| `/setup_where_play канал [роль]` | канал карточки и роль коллеров |
| `/where_play код команда` | указать community-сервер и нашу команду |
| `/stop_play` | завершить общий сбор |
| `/where_play_status` | текущее состояние карточки |
| `/where_play_card` | отправить карточку в текущий канал |

Карточка показывает сервер, код подключения, регион, карту, онлайн и команду,
и обновляется в фоне (`WHERE_PLAY_POLL_SECONDS`) с ETag-кэшем запросов.
Если источник недоступен или отдаёт устаревшие данные, карточка помечается
предупреждением и показывает последние известные значения.

Кнопка «Я коллер» доступна администраторам и роли коллеров, переносит участника
в комнату в категории `TEMP_VOICE_CATEGORY_ID` и добавляет его в список карточки.

Источник данных — сторонний сервис WardogServers. Внешние значения
экранируются и ограничиваются по длине перед выводом.

## Личные дела (анкета в клан)

| Команда | Назначение |
| --- | --- |
| `/setup_dossiers форум [канал]` | привязать форум тикетов и канал проверки |
| `/approve_interview` | пометить заявителя как допущенного к анкете |
| `/review_dossier` | открыть анкету на проверку в тикете |

Схема работы:

1. Заявитель открывает тикет из панели заявок.
2. В тикете появляется кнопка «Расскажи немного о себе» — но она активна
   только после `/approve_interview` от администратора.
3. Заполненная анкета сохраняется как черновик и уходит администратору:
   `/review_dossier` показывает карточку, а кнопка публикации создаёт тред.

Анкета: ник, имя, город, Steam ID и две специализации из шести — «Штурмовик»,
«Медик», «Механик», «Строитель», «Пилот», «Снайпер». Специализации должны
различаться, лишние пробелы и невидимые символы вырезаются, длина полей
ограничена. Пустые город и Steam ID администратор уточняет прямо в
`/review_dossier`, после чего публикуется исправленная версия.

Публикация создаёт тред в форуме, вешает картинку специализации и выдаёт роли.
Если тред создать не удалось, публикация помечается незавершённой и кнопка
остаётся активной — повторное нажатие продолжает с того же места, без
дубликатов. Черновик хранит ревизию, поэтому устаревшая кнопка не перезапишет
более новую анкету.

Хранение — таблицы `dossier_settings`, `admissions`, `dossier_drafts`,
`dossiers`, поэтому анкеты и статусы переживают перезапуск бота. Права: админ,
управление ролями и право говорить в канале проверки.

## Инфраструктура

- **Веб-панель** (`PANEL_*`): тикеты, автомод, опросы, розыгрыши, дни
  рождения, временные комнаты, расписание, бэкапы, настройки, конструктор
  эмбедов, загрузка файлов. Внутренняя: публичный reverse proxy убран, доступ
  по паролю/токену, опционально Discord OAuth2 и роли admin/moderator/viewer.
- **Расписание** (`scheduler`): отложенные сообщения по времени.
- **Резервные копии**: консистентные SQLite-бэкапы по интервалу с retention
  (`DB_BACKUP_*`), экспорт БД из панели, миграция на PostgreSQL.
- **Health**: `/health`, `/status`, логи старта/остановки, отчёт по памяти
  (`RAM_REPORT_*`).
- **Аудит**: `admin_audit` — кто и что менял в настройках сервера.

## Настройки сервера

Часть функций включается по ID из `.env` или через `/setup`:

- каналы и роли для настройки, логи (`BOT_LOG_*`, `*_LOG_CHANNEL_ID`),
- `RULES_MESSAGE_ID` / `RULES_ROLE_ID` — правила-гейт,
- `BIRTHDAY_*` — анонсы дней рождения,
- `SERVER_STATS_*` — счётчики,
- `RAM_REPORT_*` — отчёты по памяти.

Все значения читаются из окружения в `app/config.py`; секреты в репозитории
нет — заполните `.env` из `.env.example`.
